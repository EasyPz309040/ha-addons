ha-addons — solution architecture

Home Assistant add-on shells for a personal home lab: two independent add-ons, each its own sidebar entry, both public repos with no proprietary logic baked in. Cluster Control provisions and patches a four-node k3s fleet via Ansible, pulled from a private repo at runtime. Market Agent is a live, notification-driven client for xWeb's Market Agent workflow — this is the front-end half of that integration; xWeb's own diagram covers only its backend API and workflow architecture, never a specific client's internals.

PlaybookWhat it does
provision-cluster.ymlIdentity, packages, boot config, k3s membership, the pi2 NFS export, OLED/fan hardware — reads current state first and only changes what's actually wrong. Safe to re-run any time, on any host, from a fresh image or a live node alike.
cluster-update.ymlCordon → drain → patch → reboot → wait for Ready → uncordon. Workers first, storage node (pi2) last, control plane last — three explicit plays, not inventory declaration order.
backup-datastore.yml / backup-secrets.ymlNightly. Secrets are the one thing that doesn't rebuild from git on its own, so that backup is what actually matters for recovering a dead control plane.
flux-reconcile.ymlForces Flux to pull and apply PiCluster git immediately, instead of waiting out its own poll interval.
redeploy-xweb.ymlForce-restarts xWeb to re-pull its floating :latest tag, comparing the image digest before/after so a run against a not-yet-published build is a visible no-op, not a silent failure.
